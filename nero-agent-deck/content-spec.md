# nero-agent 演示内容 spec

## 项目事实

- 产品名：nero-agent。
- 定位：基于 Mastra 的自托管智能体平台。
- 使用者：管理员开户的小范围用户，不是开放自助注册的多租户产品。
- 核心闭环：网络搜索、工作区文件读写、会话记忆、周期定时任务，发生在同一个会话体系里。
- 界面：React 19 + Vite + Tailwind，中文优先；左侧会话/历史，中间对话，右侧工作区。
- 智能体：Mastra Agent，默认简体中文，`maxSteps: 100`。
- 网络：Tavily 搜索、`web_fetch`。
- 文件：每用户独立工作区，按用户 + 会话落盘；`glob` / `grep` / `read_file` / `edit` / `write_file` / `list_files` / `delete_file` / `read_attached_file`。`edit` 必须带 `expectedEtag`，冲突返回 `STALE_VERSION`。
- 附件：上传、引用、下载；配额与文件数上限可配置。
- 定时任务：cron + 时区 + 起止时间；每次触发在隔离线程执行；支持暂停/恢复、执行日志、任务管理页。
- 技能：导入/创建/发布/版本/权限/停用；对话中用斜杠命令选择技能；单次任务最多 5 个技能。
- 模型：仅 OpenAI 兼容聊天接口；公共模型由管理员维护，私有模型每人独立；API Key 以 AES-256-GCM 服务端加密；`MODEL_ENDPOINT_ALLOWLIST` 限制 HTTPS 源，拒绝重定向和内网/云元数据地址。
- 安全：管理员创建账号；登录会话保存在当前标签页；Studio 仅管理员可进；沙箱命令、沙箱写入、用户文件功能默认关闭，需门禁验证后开启。
- 架构：Mastra 1.71 + PostgreSQL（用户/会话/记忆/任务）+ DuckDB（开发可观测性）+ Docker 沙箱 + Nginx Studio 网关 + ECS 单机生产形态。
- 现状边界：没有自定义 workflows；`app_permissions` / `app_role_permissions` 只建表；模型密钥不支持轮换；是否面向外部多用户演进未确认。

## 演示叙事（11 页）

1. 封面：把一次对话，变成持续的工作。
2. 产品判断：聊天框很多，能留下来的工作台很少。
3. 核心闭环：查 → 写 → 记 → 跑。
4. 界面：一个屏幕里的会话、工作区、技能。
5. 工作区：文件属于用户和会话，写入必须可验证。
6. 定时任务：不用记得回来，任务自己回来。
7. 技能：把一套做法变成可复用的能力。
8. 模型目录：公共与私有，Key 不出服务端。
9. 架构：Mastra 在中间，数据在两侧，沙箱在下层。
10. 边界：默认关闭，显式开启。
11. 收束：它不是更会聊天，而是更能把事做完。
