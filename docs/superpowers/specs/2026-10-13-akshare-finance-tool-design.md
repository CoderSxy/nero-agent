# AKShare 财经数据工具与会话分类设计

日期：2026-10-13

## 目标

在现有通用 Agent 中加入用户主动启用的财经数据能力。Composer 上方只有一个「财经数据」入口；点击入口展开「全部、A 股、基金、指数、宏观、期货」，选择第二层后才出现可移除的分类标签，并允许 Agent 使用 AKShare 数据工具。没有标签的会话保持通用行为。分类属于会话，发送消息后文字清空、标签保留；切换会话、刷新、关闭浏览器及重新登录后从服务端恢复。后续 ECS 部署 AKTools，当前轮只产出方案，不修改产品代码或服务器。

## 已有结构与决策

- `web/src/agent/AgentComposer.tsx` 是输入框；`AgentPage.tsx` 负责会话加载与新建；`AgentChat.tsx` 发送消息。
- 现有模型配置保存在会话 metadata；财经标签也使用独立的 `neroAgentFinanceCategory` 字段，不使用浏览器本地存储。现有 metadata 写入方应做读取、合并、写入并避免相互覆盖。
- `src/mastra/agents/agent.ts` 已按 `requestContext` 动态返回工具，`src/mastra/index.ts` 统一注册工具。服务器从已鉴权会话的 metadata 读取分类，覆盖任何同名客户端上下文键，再决定本次 Agent 可见的财经工具；工具执行入口再次核验分类和会话归属。没有合法分类时不提供、不执行财经工具。
- 使用 Tool 提供实时取数；不新增 Skill、独立 Agent 或自动定时采集。财经 Tool 不替代现有 `web_search`，但在已选分类且用户明确要结构化财经数据时优先使用 AKShare。

## 交互与持久化

入口只是打开分类菜单，不激活工具。`全部` 是明确的有效选择，代表启用工具但不缩小财经类目。标签显示当前分类、支持重新选择与移除；移除后立即回到通用状态。标签不属于输入文字，所以发送后不消失。普通非财经消息即使在有标签的会话中也不应触发取数。

每个已创建会话有自己的分类。历史会话缺少字段时解释为无标签。`/agent/new` 未选择分类时不创建额外会话；首次选择分类时先完成会话创建并持久化，再显示标签和允许发送，以满足未发送前刷新/退出仍可恢复。若创建或保存失败，保留输入文字、不给出已启用的标签，也不发送财经请求。并发切换分类与发送时，以发送开始前最后一次已成功保存的分类为准；保存中禁用发送或等待保存完成。切换到另一会话时取消旧会话的异步 UI 更新。

## 数据能力与边界

AKTools 在同一台 ECS 上作为独立容器运行，只监听 `127.0.0.1` 的固定端口；现有 Node/Mastra 进程通过本机 HTTP 请求它。浏览器不直接访问 AKTools，Nginx 不代理 AKTools。应用环境变量保存 `AKTOOLS_BASE_URL`，并有服务器端开关 `FINANCE_TOOL_ENABLED`；经认证的只读能力接口向前端返回此开关和可选分类。关闭或地址缺失时隐藏或禁用新增财经选择，已有标签显示为暂不可用且不启用工具；保存的分类不被清除，以便服务恢复后继续使用。

首版用版本化的接口目录清单，包含接口名、用户分类、描述、参数定义、返回字段、数据源、限制与 AKShare/AKTools 兼容版本。先挑选每个用户分类的已验证接口，`全部` 表示这些已支持接口的并集，不承诺 AKShare 全量接口。不能凭 `stock` 前缀把全部股票接口当成 A 股，也不能凭模型猜接口名。后续增加接口须更新清单与验证。检索先在选定分类的清单内进行关键词匹配，返回少量候选；再读取选中接口的参数说明；最后校验参数并调用 AKTools。AKShare 原生 `ak.search()` / `ak.interface_info()` 可辅助生成和审查清单，但 AKTools 对其 HTTP 暴露的兼容性须在本地实测，不作为首版运行依赖。

Agent 侧提供三个短描述工具：`finance_search`、`finance_interface_info`、`finance_fetch`。搜索和详情只返回与当前分类相关的小片段；取数只允许清单内接口与参数，限制日期跨度、响应行数、响应字节数、并发、超时和调用频率。工具在构造 URL 前独立校验接口名和参数值，不接受模型提供的完整 URL、任意 Python 表达式或未列入清单的参数。AKTools 当前公开路由会动态拼接并执行调用，因此即使仅绑定本机，也必须把这些约束作为上线条件。失败、空数据、过期或上游字段变化要返回可解释状态，不让模型补造数据。

返回给 Agent 的数据包含接口名、来源网站（清单可知时）、AKShare/AKTools 版本、查询参数、数据时间或时间范围、服务器获取时间、字段及单位、总行数、截断标记与有限结果。数据时间未知时显式标记“未知”，不得以获取时间冒充行情时间。页面或回答对时效和使用范围作简短说明。AKShare 数据源/接口可能变化；该功能定位为研究与参考，不提供交易执行或投资建议。

## 部署与运行

本地先用固定版本的官方 AKTools 镜像联调，并记录镜像 digest、AKShare 版本、接口兼容矩阵。ECS 阶段在 Workbench 中检查 Docker、架构、内存、磁盘、本机端口和上游连通性后部署同一镜像 digest；容器设置重启策略、资源上限、日志轮转，仅发布 `127.0.0.1:18080:8080`。先通过本机端口做服务存活与样本接口查询，再配置应用环境变量并按仓库既有发布流程部署前后端。只有服务、目录和工具链都验收通过才打开财经入口。AKTools 升级先在本地回归，再替换 ECS 容器；故障可关开关或回退上一 digest，不影响通用会话。

## 验收标准

1. 无标签会话的工具列表与普通 Agent 行为不变；直接构造或伪造分类请求也不能调用财经工具。
2. 选第二层后才有标签；标签按会话隔离，发送后保留，移除后禁用；刷新、关闭、重新登录可恢复；首选分类未发送前也可恢复。
3. 分类过滤同时作用于搜索、详情与取数；`全部` 仅覆盖已支持清单；跨类接口、非法参数和超限请求均被后端拒绝。
4. 取数结果有可核查时间、来源和截断信息；超时、空值、上游错误、AKTools 不可用时明确报错且不编造数据。
5. AKTools 只在 ECS 本机端口可访问，公网端口扫描与 Nginx 路由均不能访问它；服务重启和应用回退有验证步骤。
