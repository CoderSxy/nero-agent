# 会话图表输出与渲染修复方案

日期：2026-10-17  
状态：已确认并实施。代码与浏览器验证完成；真实模型首次出图率评估待执行，详见 `docs/chart-rendering-verification.md`。

## 目标与已确认的问题

用户说“给我一个趋势图”时，默认在当前对话中展示图形；常见格式偏差不应轻易导致图表失败；失败后能看懂原因，配置修正后能够恢复。

代码对照和受控样例已确认：

- 当前项目和 datax 均安装 ECharts 6.1.0，现有证据不支持优先归因为版本差异。
- 当前 Agent 使用“可输出”图表的弱规则，缺少会话内图表与 HTML 文件之间的交付优先级。
- 当前解析器只接受 JSON；datax 使用 Function 执行对象表达式，支持 formatter 函数，不是同一种输入协议。
- 当前自动识别只接受 series 数组，漏掉 ECharts 实际支持的 series 单对象。
- 当前 ECharts 组件进入错误回退后移除画布，后续正确配置可能因找不到画布而无法恢复。受控组件测试已复现。
- 当前组件会在零尺寸容器上初始化；datax 等待容器可测量后再初始化。

尚未获得用户当次失败的原始配置，因此不能声称所有历史失败均由上述原因造成。

## 方案选择与范围

| 路线 | 特点 | 结论 |
| --- | --- | --- |
| 只强化提示词 | 降低 HTML 误选和错误格式概率，不能修复前端恢复问题 | 必须做，但单独不足 |
| 强化提示词、安全格式兼容、修复组件状态与错误提示 | 处理现有链路的主要问题，保留当前会话输出协议 | 推荐 |
| 完全复用 datax 的 Function 执行方式 | 支持任意 formatter 表达式，也会在页面执行模型返回的代码 | 本轮不采用 |

本轮不升级 ECharts、不建设多版本适配层、不新增图表工具或自动调用模型修复服务。保留原始源码和现有 Mermaid 展示能力，不改动移动端适配及时间能力的既有工作。

## 阶段一：明确输出协议和交付优先级

### 行为规则

1. 用户要求趋势图、折线图、柱状图、饼图或其他数据图表时，默认在回答正文输出完整的 echarts 代码围栏，由现有前端直接渲染。
2. 时间趋势默认使用 line 系列；用户指定其他图形时按其要求。流程、步骤、关系图默认使用 mermaid 围栏。
3. 仅在用户明确要求网页、HTML、独立报告、下载或导出文件时，选择对应文件交付。要求同时提供会话图表和文件时，两者都提供。
4. 不因图表配置较长或需要美化而自行改用 HTML。没有足够数据时先取数或说明缺失，不编造图表数值。
5. 模型仍以严格 JSON 为输出标准；前端兼容能力不作为主动生成非标准格式的理由。输出 option 本体，不输出 option 变量赋值、script 标签、初始化代码或函数。
6. 简单趋势图包含明确的 xAxis、yAxis、series，坐标和数据长度对应。格式化优先使用 ECharts 支持的字符串模板或直接在数据/轴名称中明确单位。

### 改动位置

- 新增 `src/mastra/agents/chart-instructions.ts`，集中定义图表协议和折线图、流程图的最小示例。
- 修改 `src/mastra/agents/agent.ts`，替换现有图表说明，保留文件操作规范和时间规则。

### 验收

使用相同模型与全新会话评估“已给数据，画趋势图”“生成 HTML 趋势图页面”“同时给图和报告”“无数据画图”“绘制审批流程”。分别检查会话图形、文件交付、缺失披露和 Mermaid 输出是否符合用户意图。

自动化测试检查实际模型请求收到新协议；真实模型的选择遵循率另行评估，不能用提示词包含某句话的测试代替。

## 阶段二：安全兼容常见语法偏差并补齐识别

### 解析流程

完整围栏 → 长度检查 → 严格 JSON 解析 → 受限格式规范化与 JSON5 解析 → 值检查 → option 对象 → ECharts。

默认输出标准保持严格 JSON。兼容只作用于接收端：

| 输入情况 | 处理 |
| --- | --- |
| 标准 JSON | 原样解析 |
| 未加引号的键、单引号、注释、尾逗号 | 通过 JSON5 解析 |
| 单层 `({ ... })` 外包装 | 仅移除完整的单层对象包装，再按数据格式解析 |
| 字符串中的裸换行 | 通过识别引号、转义和注释状态的纯文本扫描，将字符串内换行规范化为转义换行；不改动字符串之外的结构 |
| 不完整字符串、缺括号、缺失数值 | 报错，不猜测补全 |
| 函数、箭头函数、变量、表达式、赋值、模板字符串、HTML | 拒绝解析，保留源码并说明数据格式限制 |
| 非有限数值、非对象根节点或现有禁止的对象键 | 拒绝进入渲染器 |

保留原始源码用于展示、复制和定位；规范化后的对象只用于渲染。沿用 100,000 字符输入上限，并对规范化后的文本同样检查长度。递归检查 JSON5 结果，避免 NaN、Infinity 或禁止对象键借兼容路径通过。不得使用 eval、Function 或浏览器脚本执行来解析。

将 JSON5 声明为 web 的直接依赖并更新对应锁文件，不依赖 node_modules 中偶然存在的传递依赖。实现前核对该包的官方文档和当前锁文件版本。

### 图表识别

- 完整的 echarts 围栏直接进入图表解析组件，失败时显示分类错误。
- json 或无语言围栏仅在结构具有明确图表特征时自动提升为图表，支持 series 单对象和 series 数组。
- 普通 JSON 不自动变成图表；只有 xAxis 或 dataset、但缺少明确系列结构的普通 JSON 不猜测为图表。
- timeline/baseOption 等特殊配置优先要求显式 echarts 围栏，本轮不做泛化的配置猜测。
- 未闭合的流式围栏继续显示代码，不能因兼容解析而提前绘制半成品。

### 改动位置

- 修改 `web/src/agent/markdown/echarts-option.ts`：统一解析、值检查与识别；返回可区分失败原因的结果。
- 修改 `web/src/agent/markdown/markdown-renderer.tsx`：继续沿用完整围栏判定，接入新的识别结果。
- 修改 `web/package.json` 和对应锁文件。
- 新增 `web/src/agent/markdown/echarts-option.test.ts`，扩展 `web/src/agent/MessageList.test.tsx`。

### 验收

覆盖以上输入表、字符串内真实/转义换行、注释中的引号、series 单对象、普通 JSON、超长输入及未闭合围栏。使用带副作用标记的函数/表达式样例，确认解析失败且副作用从未执行；不能仅检查返回 null。

## 阶段三：修复组件恢复和尺寸生命周期

### 配置切换与错误恢复

- 状态与当前源码版本绑定。配置从 A 更新到 B 时，旧配置的错误不再遮挡新配置的画布。
- 可采用外层解析组件与按源码版本挂载的内层画布组件，避免在画布不存在时等待 effect 清理错误的死循环。
- 内容修正后自动尝试渲染新配置；不必刷新页面或重复向模型提问。
- 记录当前配置下用户主动选择的图形/源码视图，容器 resize 或主题变化不得抢回图形视图；新配置默认尝试图形。
- 异步加载返回时只允许更新仍然有效的当前组件，防止旧配置覆盖新结果。

### 尺寸与资源管理

- 在模块已加载且容器宽、高都大于零时才调用 echarts.init。
- ResizeObserver 在等待尺寸阶段就建立；容器从隐藏变为可见时初始化或 resize。
- 注册 window resize 作为补充；组件卸载、配置替换时清理监听、observer、待执行动画帧并 dispose 实例。
- 初始化、setOption 和 resize 的异常进入受控错误状态；不能留下未处理 Promise 或回调异常。
- 同一实例每次配置只应用一次，不在每次 ResizeObserver 回调重复 setOption。

### 改动位置

- 修改 `web/src/agent/markdown/EChartsBlock.tsx`，必要时在同目录拆出画布子组件。
- 新增 `web/src/agent/markdown/EChartsBlock.test.tsx`；继续运行已有消息与模块加载测试。
- Mermaid 本轮保持现有解析和安全配置；回归验证正确语法、错误后修正和源码切换，不照搬 ECharts 的 JSON5 兼容。

### 验收

覆盖：渲染失败后传入正确配置；解析失败后传入正确配置；模块失败后切换新内容；初始宽度零后变为有效尺寸；源码/图形切换；卸载时模块加载尚未结束；快速替换配置；ResizeObserver 与 window resize；实例销毁。

## 阶段四：错误分类、回归与效果验证

### 对用户显示的错误

| 阶段 | 提示示例 | 交互 |
| --- | --- | --- |
| 输入过长 | 图表配置过长，暂无法展示 | 保留源码及复制能力 |
| 数据语法 | 图表配置格式不正确；请使用 JSON/JSON5 数据，不支持函数或变量 | 保留源码；可获得解析器提供的行列位置 |
| 根结构/数值/禁止键 | 图表配置包含不支持的数据结构或值 | 展示具体校验原因，不笼统归因为版本 |
| 模块加载 | 图表模块加载失败，请刷新页面重试 | 区分网络/构建资源加载与配置错误 |
| 初始化或 setOption/resize | 图表配置已解析，但渲染失败 | 保留源码，显示经过文本转义的错误原因 |

错误说明作为普通文本展示，不执行其中的 HTML。单个图表失败不能导致整条消息、其他图表或聊天页面崩溃。源码查看和复制必须在失败时仍可用。

### 自动化验证

1. 解析器测试验证输入协议与副作用不执行。
2. 组件测试验证状态恢复、尺寸等待、视图选择和资源清理。
3. 消息测试验证完整/不完整围栏、json 自动识别、普通 JSON、Mermaid 和周围正文不受影响。
4. 用实际 ECharts 6.1.0 的 SVG SSR 对标准折线图、柱状图、series 单对象等固定配置做冒烟验证，避免测试仅证明 mock 接收到对象。
5. 针对浏览器环境，手动检查桌面和窄屏下隐藏后显示、历史消息打开、源码切换及 resize。

运行 web 定向测试、web 全量测试、后端相关测试和构建。使用项目 npm scripts；当前目录有运行中的 Mastra dev 服务时，在临时副本构建，不强制清空其输出目录。既有 TypeScript/磁盘保护失败与本次新增错误分开报告。

### 模型效果评估

至少准备 10 条带明确数据的固定问法，每条用相同模型在新会话运行 3 次；分别记录是否首次返回正确围栏、是否误选 HTML、配置能否解析和绘制。额外加入明确要求 HTML、无数据、流程图的对照样本。

目标为这 30 次图表请求均首次采用会话图表协议且可渲染；这是验收目标，不是对所有模型的永久保证。若仍出现路由偏差，先分析具体调用记录，再判断是否需要后续增加显式图表工具或结构化输出约束，不在本轮预先引入新子系统。

## 实施顺序与交付

按一 → 二 → 三 → 四实施，可以作为一次完整修复交付；各阶段独立记录测试结果。

最终交付包含：明确的图表输出协议、安全解析兼容、series 单对象识别、可恢复的渲染组件、可区分的错误提示、回归测试及模型评估记录。真实模型评估未执行时必须明确标注，不用模拟 HTTP 测试替代。

本方案仅为修复设计，尚未安装依赖或修改业务实现。实现时遵守当前项目 AGENTS.md；本轮不新增 Agent、工具、工作流或 scorer，因此无需增加新的 Mastra 注册项。
