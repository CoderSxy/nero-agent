# 公共与私有模型目录设计

日期：2026-10-04

状态：设计已在会话中逐段确认，待书面审阅
目标读者：后续使用 Cursor 实施的开发者

## 1. 目标和已确认的决定

现有独立 Agent 页面从 Mastra 的 `listAgentsModelProviders()` 读取“已连接”供应商，在线程元数据中保存 `provider/model` 字符串，并在 `useChat.sendMessage()` 中把该字符串作为 `model` 参数发送。记忆模型从客户端 `RequestContext` 读取同类字符串。这样的连接状态依赖服务器环境变量，无法区分平台共享凭据与用户自有凭据。

本次改造的目标是：管理员在 4111 端口管理**公共模型及其 API Key**，所有登录用户可选择；每个用户在独立 Agent 页的「设置 → API Key 管理」维护**私有模型及其 API Key**，仅本人可见、可选和可调用。两类模型都可用于现有 Agent 的会话模型与记忆模型。移除独立页面原有的供应商连接列表和基于环境变量连接状态的选择逻辑。

已确认的产品决定：

1. 数据库使用独立的公共模型表和私有模型表，而非一个带 `scope` 字段的混合表。两表共用服务端验证、加密与连接构造逻辑。
2. 第一版只支持 OpenAI 兼容的聊天接口。Anthropic、Gemini 等原生协议不纳入这一版；若其网关提供 OpenAI 兼容端点，可以按兼容接口接入。
3. 4111 端口新增独立的公共模型管理页，从 Mastra Studio 的「设置」提供入口；不直接修改上游 Studio 内部组件。该管理页可以要求管理员单独登录一次。
4. 独立 Agent 页在现有设置菜单中增加「API Key 管理」子菜单，供登录用户管理本人私有模型。现有会话模型、记忆模型及主题设置保留。
5. 服务端保存凭据；浏览器、线程元数据和普通模型列表均不得收到明文 API Key。

## 2. 范围与非目标

本次覆盖数据库迁移、服务端模型目录和权限 API、模型连接解析、现有 Agent 的聊天及记忆调用、两个管理界面、线程模型选择迁移、必要测试及操作文档。保留现有 Agent、工具、会话和登录体系。

第一版不做原生供应商协议、多凭据共享池、按用户计费、模型发现、自动拉取供应商模型列表、批量导入、用户间共享私有模型，也不改造 Mastra Studio 上游的 Agent 配置页。原有 `.env` 中的供应商 Key 不自动写入数据库；管理员需显式创建公共模型记录。

## 3. 方案比较

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| `public_models` + `private_models`，共用服务层 | 表级区分权限和所有权，符合产品语义；查询直观 | 两表迁移和 CRUD 需要复用代码 | 采用 |
| 单表加 `scope`、`owner_id` | CRUD 较少 | 所有权约束更复杂，偏离已确认的两表要求 | 不采用 |
| 模型表再拆独立凭据表 | 同一 Key 可被多模型引用 | 凭据生命周期、删除和权限关系增加复杂度 | 第一版不采用 |

每条模型记录持有自身的加密凭据。若以后需要一个 Key 关联多个模型，再通过独立迁移拆凭据表，当前 API 的模型引用格式不因此改变。

## 4. 数据模型

新增迁移 `migrations/002_model_catalog.sql`；沿用当前 `scripts/migrate.ts` 的顺序执行机制。表名为 `app_public_models` 和 `app_private_models`，与现有 `app_users`、`app_sessions` 命名一致。

两表共有字段：

| 字段 | PostgreSQL 类型 | 规则 |
| --- | --- | --- |
| `id` | `UUID` | 主键，默认 `gen_random_uuid()` |
| `display_name` | `TEXT` | 非空，去首尾空格后长度 1–100 |
| `provider_id` | `TEXT` | 非空，连接标识；只允许安全的字母、数字、点、下划线和连字符 |
| `model_id` | `TEXT` | 非空，传给兼容接口的真实模型名；长度及字符做输入校验，不作为浏览器可执行文本 |
| `base_url` | `TEXT` | 非空，兼容接口的 HTTPS 基础地址，服务端校验与规范化 |
| `api_mode` | `TEXT` | `chat` 或 `responses`，默认 `chat`；只开放已实际验证的模式 |
| `api_key_ciphertext` | `TEXT` | 非空，AES-256-GCM 加密载荷；永不通过读取 API 返回 |
| `enabled` | `BOOLEAN` | 非空，默认 `true` |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | 非空，创建/修改时维护 |

`app_private_models` 另有 `user_id UUID NOT NULL REFERENCES app_users(id) ON DELETE CASCADE`。按 `user_id` 和 `enabled` 建索引。公共表按 `enabled` 建索引。公共表增加 `is_default BOOLEAN NOT NULL DEFAULT false`，用唯一部分索引保证至多一个公共默认模型；管理员可指定默认。私有表不设置平台默认。表级 `CHECK` 约束覆盖非空名称、`api_mode` 取值和基本字段长度；服务层负责 URL 与业务校验。

管理 API 返回的安全表示为 `{ ref, scope, displayName, providerId, modelId, baseUrl, apiMode, enabled, hasApiKey, keyHint, isDefault? }`。`keyHint` 最多保留 Key 的末四位，不可据此恢复凭据；创建和更新响应也只返回安全表示。`ref` 为稳定的 `public:<uuid>` 或 `private:<uuid>`，不得直接把数据库 ID 当作模型连接字符串。

### 凭据密钥与加密

使用独立环境变量 `MODEL_CONFIG_ENCRYPTION_KEY`，内容为 32 字节密钥的 Base64 编码。服务启动时校验其存在和长度；缺失时给出明确配置错误，不允许以明文写入。载荷包含版本、随机 12 字节 nonce、GCM 认证标签及密文；每次创建或替换 API Key 都使用新 nonce。数据库备份不包含该环境变量；部署文档必须说明密钥丢失会导致现有配置不可解密。Key 不进入日志、异常文本、遥测、前端状态持久化或线程元数据。更换主密钥需要未来专门的轮换流程，本版不提供静默轮换。

## 5. 服务端边界与 API 契约

在 `src/mastra/models/` 建立独立模块：输入校验、凭据加解密、仓储、目录服务、连接解析和路由分开。全部路由在 `src/mastra/index.ts` 注册，遵守仓库 `AGENTS.md`。HTTP 路由为：

| 方法与路径 | 使用者 | 行为 |
| --- | --- | --- |
| `GET /model-catalog` | 已登录 | 返回启用公共模型与本人启用私有模型的安全列表，供选择器使用 |
| `GET /model-catalog/private` | 已登录 | 返回本人全部私有模型，包括停用项，供管理页使用 |
| `POST /model-catalog/private` | 已登录 | 创建本人私有模型，Key 必填 |
| `PATCH /model-catalog/private/:id` | 所有者 | 修改非密钥字段，或显式替换 Key；缺少 `apiKey` 字段表示保留旧 Key |
| `DELETE /model-catalog/private/:id` | 所有者 | 删除本人模型；已引用会话转为不可发送，须重选 |
| `GET /model-catalog/public` | 管理员 | 返回全部公共模型，包括停用项，供管理页使用 |
| `POST /model-catalog/public` | 管理员 | 创建公共模型，Key 必填 |
| `PATCH /model-catalog/public/:id` | 管理员 | 修改配置、替换 Key、启停与设置默认项 |
| `DELETE /model-catalog/public/:id` | 管理员 | 删除公共模型；已引用会话须重选 |

所有写入请求使用结构化校验，拒绝未知/错误类型的关键字段；`PATCH` 的 `apiKey: ""` 不代表清除或替换，返回 400。删除和更新使用 `id` 加所有者条件，越权目标对普通用户统一返回 404，避免泄露其他用户记录是否存在。公共管理接口对非管理员返回 403。数据查询必须从服务端已验证的会话身份取得 `user.id` 与角色，不能信任请求 body、查询参数、线程 `resourceId` 或客户端 `RequestContext` 中自称的用户身份。

`base_url` 接受 HTTPS 公网地址，拒绝 URL 凭据、片段、环回、内网、链路本地与云元数据地址；在实际发起模型调用时还要防止 DNS 解析到私网、跳转绕过和地址重新绑定。若所用 SDK 的传输层无法可靠执行这些限制，实施时应收窄为管理员批准的域名列表，且私有模型只能选域名列表中的地址；不能仅以保存时字符串检查替代出站请求保护。开发环境的本地兼容端点通过显式环境配置单独放行，生产默认不放行。

第一版不提供“测试连接”按钮；保存只验证配置格式，实际模型调用失败在对话中显示脱敏后的错误。

## 6. 模型选择与 Mastra 调用

服务端唯一入口为 `resolveModel(ref, authenticatedUser)`，返回 Mastra 当前版本接受的 OpenAI 兼容模型配置：`{ id: "provider/model", url, apiKey, api }`。具体字段与调用方式以已安装 `@mastra/core@1.71.0` 的嵌入文档及类型为准。解析器严格区分 `public:`、`private:` 前缀；私有查询始终附带当前用户 ID；停用、删除、缺密钥或无权限均返回可识别的领域错误。只在服务端解密并创建模型实例，不把连接对象发送到前端。

现有 `agent` 的 `model` 改为按请求动态解析。独立页面发送时只传所选模型引用，不再向 `useChat.sendMessage()` 传 `model: provider/model`，避免客户端绕过服务端目录。聊天与 `memoryForRequest` 使用同一目录解析器及用户身份校验；记忆的 observation、reflection 和标题生成都使用所选记忆模型，不能有偷偷回退到旧环境变量供应商的路径。若 Mastra 内部对动态 memory 的调用阶段与认证上下文存在差异，实施者须先做集成验证，并把解析放在可信服务端入口；不能以信任客户端提交的模型配置代替验证。

线程元数据仍沿用 `neroAgentModels` 键，但新值为 `{ chatModel: "public:<uuid>|private:<uuid>", memoryModel: "public:<uuid>|private:<uuid>" }`。创建线程、修改选择及发送前都需服务端校验两个引用属于当前用户可用目录；前端列表仅用于展示。选择在下一条消息生效。默认新会话先取启用的公共默认模型，其次取第一个启用公共模型，再取本人第一个启用私有模型；没有可用模型时禁用新建/发送并提示先配置。

Mastra Studio 本身若运行 Agent 而未传模型引用，服务端使用启用的公共默认模型；若不存在公共模型，明确报“请先配置公共模型”，不能选择任意用户的私有模型。独立页面可以在没有公共模型时使用当前用户的私有模型。

### 旧线程兼容

旧线程的 `neroAgentModels` 保存 `provider/model`。读取时只在**恰好一条已启用公共模型**的 `provider_id/model_id` 与旧字符串相同时转换为新 `public:<uuid>` 引用；不自动匹配私有模型，也不按名称猜测。转换可在用户首次保存选择时写回元数据，无须全库改写。没有匹配或有多个匹配时保留历史消息，在设置中标明旧模型不可用，要求用户重新选择后才允许发送。新接口不再接受旧字符串作模型调用引用。

## 7. 界面

### 4111：公共模型管理

新增同端口 `/model-admin` 页面。通过现有 `studioChineseMiddleware` 的窄范围链接注入，在 Studio「设置」区域展示「公共模型管理」入口；该注入只添加入口，不修改 Studio 内部组件业务逻辑。管理页使用项目自有 HTML/CSS/JS，由 Mastra 自定义路由在 4111 端口提供，调用上述管理员 API。由于 Studio 与独立页面目前分别使用内存/标签页登录状态，管理页使用现有 `/auth/login` 单独登录，并将令牌仅保存在当前标签页会话；API 始终校验管理员身份。未登录展示登录表单，非管理员展示 403，不在页面里只靠隐藏按钮限制权限。

页面至少支持列表、创建、编辑、替换 Key、启停、设置默认、删除确认；显示模型名、供应商/模型 ID、接口地址、启用状态、默认状态和 Key 掩码。编辑页面留空 Key 表示保留，删除与停用前说明正在使用它的会话需重新选择。

### 独立 Agent 页：私有模型管理与选择

现有设置弹层增加「API Key 管理」子菜单，进入后可查看、添加、编辑、替换 Key、停用和删除本人私有模型，再返回原设置菜单。该管理表单使用与公共页一致的校验与掩码语义。会话模型和记忆模型下拉选项分组显示“公共模型”和“我的模型”，只包含当前可用项；当前线程引用已失效时，显示明确的不可用状态与重选提示，不能把失效模型悄悄替换为默认值。主题切换不受影响。

删除或停用当前选中的模型后，菜单与发送控件立即更新。模型名称可以重复，选项以稳定 `ref` 区分。前端绝不把 API Key 存在 `localStorage`、`sessionStorage`、URL、React 路由或 Mastra 线程元数据中。

## 8. 错误处理、验收与发布顺序

错误契约：输入错误 400，未登录 401，普通用户访问公共管理接口 403，越权/不存在 404，模型停用或线程引用失效使用明确业务错误；供应商失败不向用户回显请求头、Key 或完整底层响应。数据库不可用时禁止回退到旧的环境变量连接。任何服务端错误日志先进行凭据脱敏。

验收至少覆盖：

1. 迁移能在空库及已有身份表的库中运行；重复执行不重复建表。
2. 管理员可创建公共模型；普通用户可看可选但不可修改；两个普通用户的私有模型彼此不可见、不可调用。
3. API Key 在数据库为密文；任何列表、详情、创建/编辑响应、线程元数据和错误中均无明文；留空编辑不会覆盖旧 Key。
4. 当前用户选择公共/私有模型后，聊天调用与记忆的 observation/reflection/标题生成均使用对应记录的 URL、真实模型名和 Key；伪造其他用户的 `private:<uuid>` 必须失败。
5. 原有 `provider/model` 线程在唯一公共匹配时可继续；无匹配或歧义时展示历史并强制重选。删除/停用当前模型后不能继续发送。
6. 4111 页面入口、独立页面子菜单、保存后的即时选项更新、登录/403/空列表/请求失败状态可实际操作。
7. 移除 `listAgentsModelProviders()`、`providerModelIds()`、`VITE_AGENT_MODEL` 等旧选择路径后，项目测试、`npm run build:web`、`npm run build` 通过；使用仓库 `dev` 和 `build` 脚本，不直接调用 Mastra CLI。

实施顺序为：迁移及服务层 → 权限 API → Agent 与记忆解析 → 线程兼容和独立页 → 4111 管理页与 Studio 入口 → 文档及全量回归。先在已有测试框架中写失败测试，逐步验证，再删除旧逻辑。Cursor 实施时必须保留未提交的用户修改，不重写无关文件；任何无法可靠实现的出站地址安全限制应在实现前收窄可用地址范围并明确记录。
