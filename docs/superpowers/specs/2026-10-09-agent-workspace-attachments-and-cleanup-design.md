# Agent 工作区附件与文件清理设计

日期：2026-10-09

## 目标与范围

让用户从 Composer 上传本地文件、拖入文件或图片、选择已有工作区文件，并在发送后让 Agent 准确使用这些文件。右侧工作区显示占用量、文件和文件夹大小，支持单项与批量删除。单文件上限为 **10 MiB（10 × 1024 × 1024 字节）**，每位用户的整个个人工作区上限为 **500 MiB（500 × 1024 × 1024 字节）**。图片须能由支持视觉输入的已选模型识别；不支持视觉输入时，发送前明确提示。

本次不实现 `glob`、`grep`、`edit`，也不引入参考项目截图中的“上下文”模块。PDF、Office 等文件可以上传、引用、预览或下载，但本次不承诺 Agent 能解析其内容；不要把二进制文件经 `read_file` 转成 UTF-8 后声称已理解。

## 现状与参考

- `POST /user-files/upload` 写入当前会话目录；`GET /current-workspace/files` 与右侧 `WorkspaceFileTree` 展示整个个人工作区。现有目录条目的 `size` 为 0，工作区文件不能从 Composer 选择。
- `FileService` 有属主、线程和路径检查；`WorkspaceQuota` 默认 500 MiB、5000 文件，`maxFileSizeBytes()` 默认 100 MiB。现有上传先读取完整 multipart 文件再检查大小；配额异常也未完整映射为面向用户的响应。
- 参考 `/Users/nerosun/裂缝中的阳光/sxy/工作/tc-yyxt/tc-prime-ai-datax` 的 `ChatComposer`、`ComposerResourcePicker`、`FileTreePanel`：借鉴文件选择、上传后自动加入 Composer、图片缩略图/预览/移除、文件树选择与批量删除的交互；不迁入 Ant Design、其后端协议、文件夹上传、业务上下文面板或动画效果。

## 核心决定

1. **文件只有一份。** 本地上传落在个人工作区 `uploads/<随机 ID>/<原文件名>`；选取已有工作区文件只登记引用，不复制到当前线程。上传即占空间，Composer 中“移除”只取消本次引用，不删除工作区原件。
2. **引用由服务端签发并校验。** 客户端提交 `{source, path}` 后，服务端验证登录用户、当前线程属主、路径、普通文件类型和存在性，返回不可猜测的 `attachmentId`、名称、大小、MIME 与版本。Agent 的附件读取工具只接受此 ID，按当前用户和线程再次授权，不开放任意个人工作区路径读取。
3. **消息保存引用，不保存文件正文。** 发送消息使用客户端消息 ID 关联所选附件；持久化文件元数据和引用。文字消息里给模型明确的附件 ID/名称与使用方法，历史气泡按引用渲染卡片。原文件或图片字节留在工作区；消息表、观测日志及普通工具输出不得持久化大块 base64。
4. **原工作区文件可删除。** 历史消息仍显示当时的名称、大小和类型；点击已删文件得到“文件已删除”。正在编辑或尚未发送的选择在删除后同步标为失效，发送前再次校验，不能静默发送不存在的引用。

## 用户交互

Composer 加号弹出三个选项：“上传文件”“选择工作区文件”“添加图片”。每条消息最多引用 10 个文件。上传文件允许多选普通文件；添加图片只接受 PNG、JPEG、WebP、GIF，支持多选、粘贴与拖入。把操作系统文件拖入 Composer 时，图片走图片卡片，其余走文件卡片，均先上传到工作区再加入本次消息；拖入工作区内部文件只加入引用，不重复上传。暂不支持文件夹拖入、文件夹作为消息附件或任意格式图片。上传过程中显示进度或明确的“上传中”，失败保留可重试状态；有未完成或失败的附件时不能发送。

Composer 已选区域展示文件名、大小和来源；图片用缩略图，可点击大图预览。每张卡片有“从本次消息移除”，不删除原文件。重复选择同一路径只保留一个引用；同名不同路径分开显示。文字为空但存在已准备好的附件时允许发送，显示给 Agent 的文字可为“请查看附件”。发送成功清空本次附件草稿，失败时保留文字和附件供重试。消息历史显示相同的文件/图片卡片，不暴露宿主绝对路径。

“选择工作区文件”弹层复用右侧文件树的数据和排序策略，提供路径/名称搜索、目录展开、多选、确认/取消；只允许选择普通文件。选择 `source=agent` 时仅管理员可用，并继续按现有来源权限读文件。选择时若文件大于 10 MiB，不限制引用已有文件，但不能将超过 10 MiB 的二进制内容直接送往模型；普通文本读取受输出截断限制，图片超过模型入口允许大小时提示不可用于识图。10 MiB 是**新上传**上限，不追溯删除历史文件。

右侧文件区顶部显示个人工作区 `已用 X / 500 MiB`、剩余空间和刷新。常态点击文件仍打开已有预览层，文件行菜单提供“加入当前对话”和“删除”。“批量删除”按钮进入选择模式：每行出现勾选框及人类可读大小，文件夹显示所有后代普通文件的递归大小；顶部显示所选顶层项目数、去重后的文件数与预计释放字节数。允许选文件或文件夹；同时选中父目录与子项时只计/删父目录。确认框显示路径摘要及“删除后无法恢复”，用户确认后执行；部分失败时逐项说明、刷新列表及配额。工作区根目录及系统根目录 `shared/`、`uploads/`、`projects/`、`threads/` 不可删除，但可删除其中的文件和子目录；当前线程的 `input/`、`output/`、`tmp/` 目录本身同样保留。编辑中有未保存内容的文件被删时沿用现有编辑冲突提示，不丢弃草稿。

## 服务端接口与数据

- 保留 `POST /user-files/upload` 兼容旧调用；新增面向个人工作区的上传路径或扩展原路由返回 `{source:'personal', path, name, size, mimeType, etag}`。服务端生成 `uploads/<UUID>/<安全文件名>`，不使用客户端提交的任意覆盖路径。前后端均检查 10 MiB，服务端在读取整个请求体前设置请求体上限；原有线程文件写入工具继续按线程目录工作，但也遵守 10 MiB 新写入限制。
- `GET /current-workspace/files` 的文件大小保持原义，目录 `size` 改为递归普通文件总字节数；个人来源附带 `{usedBytes, quotaBytes, fileCount}`。列目录不跟随符号链接，不把未知/不可访问条目算作可删除文件。容量数字以服务端扫描或已核对的计数为准。
- 新增个人工作区 `POST /current-workspace/attachments`：输入 `threadId`、`clientMessageId` 和去重的 `{source,path}[]`；逐项校验并登记引用，输出附件元数据及 `attachmentId`。新增 `GET /current-workspace/attachments?threadId=...` 供历史消息卡片读取。引用记录含 `ownerId`、`threadId`、`clientMessageId`、`source`、`path`、名称、大小、MIME、ETag/内容版本和创建时间；数据库增加索引。超过 24 小时的待发送引用只能在确认对应消息未被 Mastra 持久化后清理，避免请求成功但客户端断线造成历史附件丢失。不能通过提交其他用户路径或伪造 `resourceId` 访问文件。
- 新增 `read_attached_file` Agent 工具并在 `src/mastra/index.ts` 注册；输入仅 `attachmentId`。它用可信的用户和当前线程上下文查引用、再次检查真实路径和文件状态。文本返回有限长度及截断提示；受支持的图片以当前 Mastra 版本支持的多模态内容传给模型。工具的显示/持久化结果只保留元数据与状态，不保留原图片 base64；实现前须用安装版 Mastra API 和一次真实 Agent 运行验证此约束。视觉模型不支持图片时在发送前阻断，而非退化成乱码。若无法保证多模态结果不会持久化大块数据，改用消息输入处理器做工作区引用回填与持久化脱敏，仍以同一验收标准为准。
- 新增 `POST /current-workspace/files/batch-delete`，输入规范化的相对路径数组；只允许个人来源。服务端先去重并折叠父子路径，检查每个路径的属主、存在、类型及受保护目录；返回逐项成功/失败、删除文件数、实际释放字节数与最新使用量。单项删除复用同一接口。删除时与上传/编辑的同用户写操作协调，避免计数竞争；文件删除成功才释放相应配额，失败不释放。
- 配额统一按整个个人工作区的普通文件字节数计；覆盖写按净增量预留，删除按实际字节数释放，使用数据库原子预留以避免并发超额，并提供磁盘扫描对账以包含 Agent/沙箱直接写入。硬上限不依赖浏览器校验或内存 Map。容量不足统一返回可识别错误码 `WORKSPACE_QUOTA_EXCEEDED`，前端提示：“工作区已超过 500 MiB 上限，请删除无效或过期文件后再上传。” 单文件超限返回 `FILE_TOO_LARGE` 与 10 MiB 文案。主机剩余空间保护继续执行，不能因个人配额未满而绕过。

## 安全与兼容

所有新路由通过现有 Bearer 身份及线程属主检查；使用 `relativeFilePath`、真实路径包含关系和符号链接防护；不接受宿主绝对路径、`..`、NUL、反斜杠或目录目标。上传文件名仅作显示，服务端决定存储路径；下载/预览仍走已认证的 Blob 请求。删除 `source=agent` 暂不开放。已存在的 `/user-files/<threadId>/...` 链接、线程文件工具、预览编辑能力保持可用。

图片使用已上传的私有工作区文件做预览来源，浏览器创建并释放 `objectURL`；向模型提供图片时核对所选模型能力、MIME 和尺寸，并保证请求/工具结果不会在数据库重复存储原图。不得把“图片可预览”误判成“模型已识图”。历史引用的文件变更后显示“文件已更新”，删除后显示“文件已删除”。

当前模型目录没有视觉能力字段。本次给公共和私人模型增加管理员/模型所有者可设置的 `supportsVision` 布尔值，迁移后既有模型默认 `false`；选择器返回该字段，Composer 在发送图片时据此阻断并提示“当前模型不支持图片，请切换支持图片的模型”。不能根据模型名称猜测能力。服务端也核验所选模型的同一字段，避免仅靠客户端阻断。

## 验收标准

1. 本地选取、拖入、粘贴图片、选择已有文件均生成正确卡片；工作区选择不产生第二份文件或额外占用量，移除卡片不删文件。
2. 发出仅有附件或文字加附件的消息后，Agent 能看到附件 ID 和名称；文本读取正确，视觉模型能回答图片内容问题；不支持视觉的模型发送前给出明确提示。发送失败不丢草稿。
3. 历史消息在刷新页面后仍显示附件；更新/删除文件后的状态正确；用户 A 不能引用、读取、删除用户 B 的文件，其他线程不能借用未经本线程登记的附件 ID。
4. 新上传 10 MiB 可接受，超过 10 MiB 被拒；接近 500 MiB 时并发上传和覆盖写不会超过上限；超额显示指定中文提示。上传/编辑/Agent 产出/删除后容量一致；主机磁盘保护仍生效。
5. 右侧工作区的文件夹大小是递归值；批量选择父子路径不重复统计或删除；受保护目录、路径穿越、符号链接和管理员旧工作区删除均被拒；部分失败有清楚反馈。
6. `npm test`、`npm test --prefix web`、`npm run build` 通过；使用 `npm run dev` 完成人工浏览器检查。抽查消息持久化与观测记录，确认没有 10 MiB 图片的 base64 副本。
