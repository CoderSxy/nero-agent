# Agent 右侧面板与工作区文件预览编辑设计

日期：2026-10-06

## 目标与范围

在 Agent 页面截图标出的右上区域放两个纵向按钮，分别控制 Config 和工作区文件管理右侧面板。用户可以展开任意一个，也可以都收起；同一时间最多一个面板打开。从一个面板切到另一个时，先完整播放旧面板的关闭动画，再播放新面板的打开动画。

文件管理展示当前 Agent 实际使用的工作区目录。用户点击文件后，在中间对话区域上方打开预览编辑层。可编辑文本提供保存；无法编辑的文件仅供预览或下载。修改后关闭时，用户可保存并关闭、放弃修改并关闭或继续编辑。

本次只实现目录浏览、刷新、预览、文本编辑与保存。参考项目的上传、删除、重命名、移动、压缩等管理操作不在范围内。

## 现状与参考

- `web/src/agent/AgentPage.tsx` 使用左侧会话栏、中间对话区、右侧常驻 Config 的三列布局。
- `web/src/agent/ConfigPanel.tsx` 的“工作区”卡片内嵌 `ThreadFiles`；现有文件树是平铺列表，点击文件只下载。
- `GET /current-workspace/files` 已能列出完整工作区；同路径的文件 GET 以附件方式返回二进制。个人工作区按用户隔离，旧 Agent 工作区只允许管理员访问。
- 参考项目 `tc-prime-ai-datax` 用 Monaco 编辑文本；Markdown/HTML 可切换预览；图片、PDF、PPTX、DOCX、XLSX、draw.io 等以只读方式预览，旧版 Office 或其他不支持的二进制文件提供下载。借鉴其文件类型策略和预览库，不迁入其 Ant Design、全局状态仓库和文件管理操作。

## 方案选择

推荐在现有 React 页面内新增独立的面板控制器、文件树和预览层。这样可以沿用当前的权限接口、主题和布局，避免复制参考项目与业务无关的大量状态和依赖。保留 `ConfigPanel` 的只读配置内容，但把工作区文件列表移至独立面板。

另一种方案是直接移植参考项目整套 `FileTreePanel`/`FileEditorPanel`。它耦合该项目的 opencode 文件系统适配器、Ant Design、状态仓库和其他管理功能；为了本次范围还需大规模裁剪，因此不采用。

## 交互与布局

面板状态为 `config | files | null`，初始值 `config`，保持当前桌面首次进入时的视觉习惯。两个切换按钮固定在中间区域右上、靠近面板边界，顺序与截图一致：上 Config，下文件管理。按钮使用明确的图标、tooltip、`aria-label` 和 `aria-expanded`，打开的面板高亮；再次点击当前按钮即关闭。

桌面端右侧面板占用布局宽度，中间区随之平滑伸展或收缩。使用 Motion (`motion/react`) 的布局与进入/退出动画；切换时 `AnimatePresence mode="wait"` 与单一面板状态保证旧面板退出完成后才挂载新面板。快速连续点击以最后一次目标为准，动画中不会短暂显示两个面板。尊重 `prefers-reduced-motion`，在减少动态效果时直接切换且仍保持状态顺序。窄屏时右侧面板作为覆盖式抽屉，以便按钮仍可访问；预览编辑层始终只覆盖中间对话区域，右侧目录仍可见。

文件树展示完整当前工作区，目录默认折叠，可逐级展开，目录优先、名称排序；提供类型图标、选中态、路径提示、刷新、加载中/空目录/错误状态。点击目录只切换展开，点击文件打开预览编辑层；刷新保留仍存在目录的展开状态。

预览层顶部显示文件名和相对路径，提供关闭，以及只读预览的下载操作。可编辑文本显示“保存”及未保存状态。编辑态中 `Ctrl/Cmd+S` 触发保存。保存成功更新原始内容与版本标识；失败时保留当前编辑内容和预览层。点击关闭且内容已改动时显示三个选择：保存并关闭、放弃修改并关闭、继续编辑。正在保存时避免重复提交。切换文件时沿用同一未保存确认流程。会话路由变化不会销毁尚未处理的编辑草稿。

## 文件类型与预览

文本/代码文件（包括无扩展名但经内容检测是文本的文件）使用 `@monaco-editor/react` 编辑，按扩展名选择语言，高亮并自动布局。Markdown 与 HTML 可在源码和渲染预览之间切换；HTML 在受限 `iframe` 中渲染，不赋予同源权限。预览只是查看，保存仍针对文本源码。

PNG、JPEG、GIF、WebP、SVG 等图片只读预览。PDF 使用 `react-pdf`，PPTX 使用 `@aiden0z/pptx-renderer`，DOCX/XLSX/draw.io 使用 `@open-file-viewer` 对应插件；这些格式均只读且不显示保存。旧版 Office、未知二进制及解析失败的文件显示原因并提供下载。大型文件在线预览前检查大小，避免浏览器无响应；达到上限时保留下载入口。预览库按需加载，避免加重初次进入 Agent 页面的加载。

文件数据经已授权的 `apiFetch` 获取为 Blob，再创建并清理 `objectURL`；不将需 Bearer 身份验证的地址直接交给第三方预览器。

## 服务端与数据流

沿用当前 `GET /current-workspace/files` 和文件 GET，文件 GET 增加内容版本标识（ETag）。新增 `PUT /current-workspace/files/*`，仅覆盖已存在的可编辑文本文件。请求携带原始 ETag（`If-Match`）与 UTF-8 文本，响应返回新 ETag。服务端在同一用户、同一工作区来源下再次校验身份与授权、相对路径、目标类型、文本编码和大小；对旧 Agent 工作区继续执行管理员限制。若文件已变化，返回 412 并拒绝覆盖；若只读、缺失、二进制或超限，返回明确错误。保存后刷新文件树元数据。

使用安装版本的 Mastra `WorkspaceFilesystem.readFile/writeFile` 接口；路径仍经当前的 `relativeFilePath` 与 contained 文件系统限制。只对当前工作区写入，不修改线程附件接口，也不绕过已有沙箱和工作区隔离。

## 组件边界

- `AgentPage` 管理面板目标、当前文件、预览层及文件刷新信号。
- 面板控制器负责顺序动画与按钮可访问性，不持有文件数据。
- 文件树负责列表、展开、选中和选择文件事件。
- 文件预览层负责类型分派、编辑草稿、保存、关闭确认和 Blob 生命周期。
- 客户端文件模块负责读取 ETag、获取内容及条件保存。
- `src/mastra/files/routes.ts` 增加保存路由；复杂的文本与版本校验提取为可单独测试的服务函数。所有 API 路由继续在 `src/mastra/index.ts` 注册。

## 验收

1. 两个按钮可分别展开/收起面板；可以都关闭，但不会同时打开。
2. Config 与文件面板互切时，旧面板退出结束后新面板才进入；快速点击、窄屏和减少动态效果均保持正确。
3. 文件树显示当前工作区所有层级；管理员旧 Agent 工作区来源与普通用户个人工作区不会串数据。
4. 点击文本可编辑并保存；只读类型可预览或下载，界面不显示保存。
5. 修改后关闭有三种选择；保存失败或版本冲突不丢草稿；切换文件亦遵循此规则。
6. 服务端拒绝未授权、路径穿越、符号链接逃逸、只读/二进制写入、超限写入和旧版本覆盖。
7. 前后端测试及项目 `npm run build` 通过，浏览器手工检查布局与动画。
