# Agent 历史对话全文搜索设计

日期：2026-10-11

## 目标与边界

在左侧栏“历史对话”标题右侧增加搜索图标。点击图标或按 `Ctrl/Cmd + K` 打开搜索弹窗，搜索当前登录用户历史会话中的问题和 Agent 回答。结果展示会话标题、命中的问题或回答片段；选择结果后进入对应会话并滚动到该轮用户消息。交互参考 `tc-prime-ai-datax/apps/web/src/components/history-search/`，使用同一个第三方库 `cmdk`（参考项目依赖版本 `^1.1.1`）提供键盘结果导航。弹窗及索引按本项目 React、Mastra 消息结构和现有 CSS 实现，不引入参考项目的 Ant Design 或共享业务包。

搜索范围只包括当前登录用户可读取的 Agent 会话。首轮打开按当前会话列表的倒序加载最近 50 个会话；加载完成后可搜索这些会话，若总数超过 50 则提供“加载全部会话内容”。全文加载失败时保留最近 50 个会话的可用结果并允许重试失败项。搜索不包含工具参数/结果、推理过程、观察标记、附件协议文本、其他用户数据、会话标题单独命中或文件内容。不新增 Mastra 工具、索引服务、数据库迁移、向量搜索或服务端搜索路由。

## 现有接入点

- `web/src/agent/ThreadSidebar.tsx` 已有“历史对话”标题和列表模式切换按钮，可在该行右侧并排放置搜索按钮。
- `web/src/agent/AgentPage.tsx` 拥有登录用户 ID、会话列表、路由导航和当前会话加载状态；它负责把搜索选择转换为 `/agent/:threadId?targetMessageId=:messageId`。
- `web/src/agent/thread-scope.ts` 的 `loadScopedThread(threadId, resourceId)` 先检查线程属主，再逐页读取全部消息。搜索复用此方法，不直接用无归属检查的客户端调用。
- `web/src/agent/message-parts.ts` 将 Mastra 消息转为可展示片段；搜索只抽取 `kind: 'text'`，并利用 `isUserMessage` 识别用户消息及用户信号。用户附件协议由 `messageParts` 清理。
- `web/src/agent/MessageList.tsx` 逐条渲染消息，`AgentChat.tsx` 控制滚动容器和自动跟随；需要给目标消息稳定标识，并在目标消息出现后滚动定位。

## 搜索文档与匹配规则

一个搜索文档对应一轮用户提问。结构为 `{ threadId, threadTitle, threadUpdatedAt, userMessageId, questionText, answerText }`。按消息创建时间正序遍历：遇到用户消息结束上一轮并开始新一轮；其后到下一条用户消息之前的助手可见文本顺序拼接为回答。无有效用户文本的消息不生成文档；孤立的助手消息不纳入搜索。用户/助手只取可展示的 `text` 片段；空文本、工具调用、推理、观察、附件协议和结构化错误提示不进入索引。旧消息结构可由 `messageParts` 的兼容分支提取。

查询先 `trim`、`NFKC` 规范化、按 Unicode 小写转换，采用字面子串匹配，不把用户输入当正则表达式。问题和回答都可命中；同一轮只返回一个结果，问题优先于回答。结果先按问题命中优先，再按会话更新时间降序排列，最多显示 100 条，同时显示匹配总数。结果片段围绕命中位置截取，最多约 180 个原文字符；原文与规范化文本长度不一致时也必须得到有效片段，不能因索引偏移出错。高亮只作用于文本节点，不注入 HTML。空查询显示引导，零结果显示明确空态。

## 加载、缓存与更新

打开弹窗时才读取消息，不在页面初始化时建立全文索引。最近 50 个会话以最多 5 个并发请求加载；弹窗展示已完成数/总数。加载全部时只请求剩余会话。用户关闭弹窗后停止发起新的分页批次或忽略已过期结果，重新打开可以继续利用已缓存数据。切换账号或会话列表时，用 generation/abort 防止旧请求覆盖新用户结果。

浏览器 IndexedDB 缓存每个会话的搜索文档，键包含当前用户 ID 与会话 ID，版本使用会话 `updatedAt`；存储不可用时退回内存缓存。删除的会话从当前用户缓存移除。会话标题/更新时间变化导致下次读取时重建缓存；当前会话成功发送或回复结束时还要显式失效该会话缓存，以防列表时间戳尚未刷新时搜不到最新内容。失效操作也须防止较早启动的请求把旧索引写回。缓存只保存在本机浏览器，UI 不展示别人的缓存。失败项不记作空结果；最近批次失败要显示失败数与“重试加载”，全部批次失败仍保留最近已就绪的搜索范围并允许重试。

## 唯一 IndexedDB 数据库约束

当前项目尚无 IndexedDB 使用。前端在本应用的同源上下文中只允许创建**一个由项目管理的数据库**：`nero-agent-client`。其名称、版本、对象仓库创建与连接生命周期统一由 `web/src/storage/indexed-db.ts` 管理。历史搜索是首个使用者，只在这个数据库内创建 `historySearchDocuments` 对象仓库；不得单独创建 `nero-agent-history-search` 数据库。业务模块不得直接调用 `indexedDB.open()`、`indexedDB.deleteDatabase()`，也不得引入会自行创建第二个 IndexedDB 数据库的持久化依赖。`cmdk` 只承担交互，不负责持久化。

共享模块初始数据库版本为 1，集中导出数据库名、版本、仓库名和 `openAppDatabase(): Promise<IDBDatabase>`。并发调用共用同一个打开中的 Promise/连接；`versionchange` 时关闭旧连接。未来功能需要持久化时，应在**同一个数据库**中增加自己的对象仓库，递增数据库版本，并只在共享模块的 `onupgradeneeded` 中实施非破坏性升级；不得为了新功能增加新的数据库名、覆写旧仓库或删除整个数据库。升级前明确旧数据保留与迁移规则。业务仓库读写可有各自的适配器，但只能通过共享模块取得连接。

构建流程加入源代码守卫：扫描 `web/src` 的生产代码（排除 `*.test.*` 测试夹具），只允许共享模块出现直接打开或删除 IndexedDB 数据库的 API 调用；发现其他位置调用则构建失败并提示改用共享模块。这个静态守卫不能识别第三方库内部行为，因此新增持久化依赖仍需在依赖评审中确认不会另建数据库。IndexedDB 不可用、被浏览器阻止或打开失败时，历史搜索缓存退回内存；共享模块的失败不能阻止会话搜索本身。

## 弹窗与导航

搜索按钮 `aria-label="搜索历史对话"`，与现有列表模式按钮并排，不改变默认的分组模式。`Ctrl/Cmd + K` 在 Agent 页面打开/关闭弹窗；输入框有明确标签和占位“搜索历史对话中的问题和回答”。弹窗使用 `role="dialog"`、`aria-modal="true"`，打开后聚焦输入框，`Escape` 关闭并把焦点还给打开它的按钮；点击遮罩可关闭。`cmdk` 处理上下键、循环选择和 Enter。中文输入法组合输入期间的 Enter 不选择结果或关闭弹窗。

选择结果后关闭弹窗并导航到目标会话，路由查询参数使用 `targetMessageId`。`MessageList` 为每条真实消息添加 `data-message-id`；`AgentChat` 在消息加载完成、目标元素渲染后滚动该消息进入聊天视口，并短暂高亮。每次目标变化只定位一次，后续流式更新或尺寸变化不得重复拉回该位置。定位时暂停“始终跟随最新消息”，避免滚动被后续布局更新覆盖；目标 ID 不存在时保持会话正常显示，不报错或跳到错误消息。同一会话内再次选择其他结果也必须重新定位。导航后用户手动滚动仍沿用现有自动跟随判断。

## 验收标准

1. 历史对话标题右侧能看到搜索图标；按钮和 `Ctrl/Cmd + K` 都能打开弹窗，键盘上下键/Enter 可选结果，Esc 可关闭，中文输入法确认文字不会误选。
2. 最近 50 个会话和“加载全部会话内容”范围准确；问题与回答都可搜索，命中片段、优先级、总数及 100 条展示上限正确。空态、进度、失败重试可理解。
3. 选择结果进入对应会话并定位到对应用户消息；跨会话和同会话再次选择均有效，不影响现有聊天自动跟随。
4. 只使用经过 `loadScopedThread` 归属校验的历史消息；账号切换、删除会话、缓存失效、IndexedDB 不可用和并发请求乱序不会泄露或展示过期数据。
5. 浏览器只创建 `nero-agent-client` 这一个项目数据库；搜索索引位于 `historySearchDocuments` 仓库中。共享连接、版本升级与构建守卫可验证；其他源码位置直接打开第二个数据库时构建失败。
6. `npm test --prefix web`、`npm run build:web` 和 `git diff --check` 通过；若仓库已有无关失败，记录具体失败并验证新测试及构建结果。
