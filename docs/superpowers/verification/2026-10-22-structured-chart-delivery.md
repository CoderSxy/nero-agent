# 结构化图表交付修复

用户确认的修复重点：固定取数后的数据和来源；最终交付受 Schema 约束，由平台组装 ECharts；错误原因归属具体回答。当前工作区直接实施，不新建 worktree，不更改用户默认模型。

## 实现

- 纯图表轮使用原生 JSON Schema，模型提交 status / reason / title / dataset，dataset 包含 categories、具名 series 和 sources。平台负责坐标轴、图例、系列与 ECharts JSON，不再让模型布局字符图或网页。
- 真实 Kimi 接入在带 response_format:json_schema 时仍返回普通文本。正常取数后可直接调用同一 Schema 的 submit_chart_data 提交数据；唯一一次格式修正强制使用同一 Schema 的 submit_chart_data 纯数据工具，强制 named tool choice；没有网络、文件或依赖安装副作用。提交后通过本地响应完成渲染，不增加模型请求。主调用预算仍为 8，格式修正最多 1 次。
- 数据类别与序列长度、顺序、有限数值、七天天气覆盖进行校验。用户数据按类别/具名数组核对；在线数据与实际成功来源中的结构化数组核对。仅出现在搜索 query 中的网址不成为来源。纯文本网页无法核对为结构化序列时不自动猜数成图。
- 校验通过的数据深拷贝、冻结、计算 SHA-256；表现层只从该快照构建，不重新生成数值。显式样式续问可恢复上一张图的快照和来源，不能将新数据请求悄悄套用旧快照。
- 流式 pending 标记使内部协议 JSON 不进入正文；ready 标记提供平台生成的图表与来源，已有 ECharts 组件渲染。最终持久化更新同一回复 ID，保留工具/推理，避免额外错误消息改变排序。
- 区分 insufficient-data、missing-chart、invalid-json、invalid-data、unverified-source、invalid-option、budget-exhausted。错误显示于对应回复，不再由聊天底部统一的模糊横幅显示。
- HTML、导出、附件、技能及混合任务沿用原交付逻辑；历史围栏图表继续支持。

## 回归与复审

- 初始失败：缺少 response_format、结构化 ready 被误判 missing-chart、明确数据不足仍重试；对应真实 Mastra Agent 集成测试已覆盖。
- 初始失败：前端暴露 raw JSON、ready 不显示 canonical 图表；messageParts 回归已覆盖。
- 独立只读复审三项问题均接受：数字集合丢失类别绑定、样式续问失去来源、搜索参数被误认证为来源。针对交换/重复数字、未观察来源、更改在线数值、空搜索结果、日期重排和图表类型续问补测。
- 修正仅保留纯数据 handoff，无取数重放；兼容 provider 无视工具限制的硬预算回归保留。

### 排查中修复的接口边界

- 非结构化 HTML 页面现在在图表专用 web_fetch 返回时明确要求结构化 JSON，不把 HTML 摘要或估算当作已核对数据；普通 HTML/技能任务的取数工具不受此约束。
- Mastra processInputStep 接收的工具可能已经转换为 SDK 格式，没有 inputSchema。重新包装时使用对应 builtin 的 Schema 作为 fallback，防止 url/question 参数丢失。已对实际 provider 请求的 required/properties 补回归。
- 一个中间在线样本因来源无法核对被正确阻止；另一个中间样本暴露 url Schema 丢失，修复后才通过最终在线验收。没有将这些失败样本改写成成功。

## 能力边界

仅确认了当前 Kimi 接入及上述图表场景。其他 provider 若拒绝工具/Schema，仍需按具体接口验证；不以全局关闭校验掩盖问题。缺少可核对结构化来源、缺天或缺值时明确失败。自定义 HTML、导出和技能任务保留原路径。本批没有替换记忆模型或调整记忆策略。
